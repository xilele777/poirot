状态：已完成并归档。首次写作：2026-10-02。

依据：[代码质量评审](../../reviews/0003-2026-10-02-评审-代码质量目录架构与能力闭环.md)。目标是修复已证实缺陷、建立可重复交付检查，并让能力声明与运行行为一致。保留当前领域划分，不以文件搬家代替可靠性改造。

## 阶段与验收

- [x] A：产物边界。统一虚拟路径/宿主路径校验，拒绝 traversal、跨平台路径和符号链接越界；导出失败不注册成功产物；输出目录显式注入，移除 agents 对 app 的反向依赖。正常嵌套文件、恶意路径、复制失败均有回归用例。
- [x] B：记忆一致性。共享目录操作使用跨进程锁，在锁内读最新数据再修改，以临时文件原子替换；读取刷新，检索索引跟进外部变更。验证两实例、进程竞争及写入失败保留旧文件。
- [x] C：发布资源。显式包含 prompt/Skill/YAML/TS，排除测试包；提供隔离 wheel 冒烟检查，并实际构建验证。
- [x] D：能力与装配收口。集中重复的 Leader 构建参数；未提供真实模型/评估器的 multiagent 进化在启用时明确报错，不启动空转线程；修复 Skill 发布失败的假成功记录。保留手动 Skill 进化，将未接通的自动能力明确标为未交付，避免在本轮仓促引入未经验证的后台自动修改功能。
- [x] E：工程门禁与文档。最小 CI 覆盖默认测试、边界回归、安装包检查；建立 docs 能力/限制/验证入口，校准 README 与多语言入口，收敛 learn 导航。
- [x] F：集成收口。执行相关测试、默认全量和 wheel 验收；新增独立变更记录，更新工作日志，归档本计划并新增后续验收计划。

## 范围与执行约束

修复直接关联的缺陷并补行为测试，不做无依据的大规模重命名。保留用户既有未提交资料。无需真实密钥的检查先全部完成；真实 LLM/Docker 的成本、环境和效果评估不以 mock 测试替代。暂不推送或发布。

## 后续独立阶段

自动 Skill 进化/回滚和专家进化需要先明确固定任务集、基线、评估器与发布权限；达到这些条件后再实现调度闭环。中文召回、磁盘会话恢复、全面静态类型检查另行安排，不混入本轮缺陷修复。
