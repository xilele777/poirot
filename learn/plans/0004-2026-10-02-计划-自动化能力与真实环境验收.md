# 自动化能力与真实环境验收

状态：待执行。首次写作：2026-10-02。

前置结果：[数据边界与工程交付收口](../changes/0010-2026-10-02-变更-修复数据边界并收口工程交付.md)。本计划区分未接通的产品能力与已完成的基础修复，不能仅以构造组件成功作为验收。

## 1. 自动进化的实验与发布契约

- 明确 Skill / 专家进化分别修改什么、谁触发、是否默认开启，以及批准/回滚策略。
- 定义固定真实任务集、候选/基线对照、失败类型、预算、模型版本和最小改进证据。
- Skill 自动循环接入应用生命周期；发布与评估记录需要事务或可恢复的发布状态，失败不能只留成功版本指针。
- 专家进化注入真实 LLM caller 与 task evaluator，统一 L2/L3 registry，线程可停止；验收后才能解除当前应用入口的不可用检查。
- 回滚、取消、超时、重复触发、重启和失败恢复都应有完整链路用例。

## 2. 真实环境验收

- 使用专用测试配置验证 Local/Docker、主/子 Agent、外部 CLI 专家和产物导出。
- 执行 integration marker 测试，分别记录通过和跳过；真实 API 费用与任务预算需要先明确。
- 推送后核对新增 GitHub Actions 的真实结果；按需要扩展 Linux 与 Python 版本矩阵。

## 3. 剩余工程债务

- 为中文记忆建立召回基准再选择分词/检索方案，避免只更换类名。
- 明确会话重启恢复要求后选择磁盘 checkpointer，并验证版本迁移和并发。
- 对 CLI Skill 分派、流式服务按行为边界拆分；不以函数行数下降作为唯一验收。
- 评估依赖锁、lint/type-check 渐进门禁及 Markdown 存储规模上限。
