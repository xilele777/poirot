# 测试隔离质量评审

日期：2026-09-28
类型：评审

## 结论

测试**覆盖**优秀（2726 个用例，多数文件带详尽的 `INVARIANT` 注释与 mock 边界
说明），但**进程级隔离不统一**。问题不在"测试太少"，而在测试之间通过全局状态
互相渗透，且依赖宿主机器状态。

## 已修复的 7 处隔离缺陷

| # | 位置 | 缺陷 | 修复 |
|---|------|------|------|
| 1 | `test_guards_selfcheck.py` | 直接 `os.environ["PATH"]="/usr/bin"` 不还原 | `monkeypatch.setenv` |
| 2 | `test_docker_runtime.py` | 模块级 `sys.modules["agent_sandbox"]` 占位不还原 | `tests/v1/fixtures/sdk_stubs.py` 统一处理 |
| 3 | `test_docker_sandbox_provider.py` | 同上 | 同上 |
| 4 | `test_claude_credential.py` | 未隔离 `ANTHROPIC_AUTH_TOKEN` 等凭据变量 | autouse fixture 清空 |
| 5 | `test_pi_installer.py` | `shutil.which("npm")` 依赖宿主 PATH | autouse fixture 默认 mock npm |
| 6 | `test_local_container_backend.py` | "宿主无 docker 才通过"的断言 | mock `subprocess.run` |
| 7 | `test_provider_config.py` | 依赖 `*_MODEL` 未设置，被 `.env` 污染 | autouse fixture 隔离 |

## 四种根因模式

1. **直接改全局状态不改回** —— 不走 `monkeypatch`，改了就污染同进程后续测试。
2. **无集中隔离设施** —— 整个 `tests/` 树零 `conftest.py`，每个文件自己想办法，
   纪律参差。同一批代码里 `test_claude_credential.py` 会认真清凭据变量，
   `test_guards_selfcheck.py` 却直接改 `PATH` —— 作者知道正确做法，只是没立成
   项目级规矩。
3. **"单元测试"混入外部依赖** —— stage5/6 要真实 Docker + 13GB 镜像、
   `test_default_strategy_e2e` 要真实 `DEEPSEEK_API_KEY` 且模块导入时
   `load_dotenv()`、`test_pi_installer` 依赖 `shutil.which("npm")`。
4. **对宿主机器有隐含假设** —— 假设 Linux、假设未装 npm、假设未设
   `ANTHROPIC_AUTH_TOKEN`、假设无 `.env`。换机器即翻车。

## 结构性信号

`tests/v1/integration/` 目录存在，但 stage5/6 两个**集成**测试放在
`unit/sandbox/` 下（文件名含 "integration"）。项目有分层意图，未执行到底。

## 与项目自我定位的 gap

README 标榜"每个模块独立设计、独立测试、独立可验证"，但测试恰好在
**进程隔离**这一层没做到"独立"，靠全局状态互相渗透。

## 根治建议（未执行，供后续规划）

1. 建 `conftest.py`，集中清理环境变量与 `sys.modules`。
2. 将 stage5/6 等需真实 Docker 的测试迁到 `integration/` 或打 marker 默认跳过。
3. 立规矩：改全局状态必须走 `monkeypatch`。

本轮已"哪里破了补哪里"修复 7 处，但未做系统性重构。
