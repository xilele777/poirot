# 建立测试环境隔离层并分层集成测试

日期：2026-09-28
类型：变更
关联：[测试隔离质量评审](../reviews/0001-2026-09-28-评审-测试隔离质量.md) ·
[测试环境隔离改造计划](../archive/plans/0002-2026-09-28-计划-测试环境隔离改造.md)

## 背景

多次全量验收均在测试上出问题。查证结论：测试**覆盖**优秀（221 个测试文件、
2700+ 用例），但**进程级环境隔离从未立成项目级约束**——整个 `tests/` 树零
`conftest.py`，污染者与受害者分散在不同文件，只在全量运行时相遇，故开发期
不可见、验收期集中爆发。

本轮修复前实测即有一条活标本：

```
6 failed, 2720 passed, 3 skipped
FAILED v1/unit/sandbox/test_stage5_integration.py  (3)
FAILED v1/unit/sandbox/test_stage6_integration.py  (3)
```

失败原因：守卫只查 `shutil.which("docker")`（CLI 在），但 Docker 守护进程未起，
"应跳过"退化为"硬失败"。

## 核心变更

### 1. 新增项目级隔离层 `poirot/backend/tests/conftest.py`

- **会话基线机制**：`_BASELINE_ENV` 在 conftest 导入时（尚未导入任何测试模块）
  快照 `os.environ`，`_isolate_environ` 在每个测试**前后**把环境重置回基线。
  这样不仅拦得住测试体内的改动，也拦得住**导入期污染**（如模块级 `load_dotenv`
  灌入的变量）——后者是"快照-还原单测试"挡不住的，因为污染发生在快照之前。
- 重置时保留 `PYTEST_*` 变量，避免误删 pytest 记账用的 `PYTEST_CURRENT_TEST`
  导致其 teardown 抛 `KeyError`（整体 `clear()` 会踩这个坑，已实证）。
- `_isolate_stub_modules`：移除测试期间新注入的假可选依赖占位模块。

### 2. 铲除污染源，撤掉受害方挡板

排查中发现真正的污染源比评审所述更深：不只
`integration/test_default_strategy_e2e.py` 的模块级 `load_dotenv()`，还有**生产
代码** `app/cli/main.py` 导入时即 `load_dotenv(.env)`；`test_recursion_limit.py`
从它导入 `_build_stream_config`，于是任何导入该模块的测试都会把整个 `.env`
灌进进程环境（实测：导入后 `OPENAI_MODEL` 由 `None` 变为 `gpt-5.6-sol`）。

- `test_default_strategy_e2e.py`：删除模块级 `load_dotenv()`，改为 `dotenv_values()`
  只读判定是否 skip，真正需要的变量用 `monkeypatch.setenv` 在用例作用域内注入。
- `test_provider_config.py`：删除下游挡板 fixture `_isolate_provider_model_env`——
  污染源已被隔离层兜住，挡板成为冗余的"治标"痕迹。

### 3. 分层集成测试与默认门禁

- `pyproject.toml` 新增 `[tool.pytest.ini_options]`：注册 `integration` marker，
  `addopts = "-m 'not integration'"` 使默认全量运行排除集成层。
- 新增 `tests/v1/fixtures/docker_guard.py`：`docker_daemon_reachable()` 以
  `docker info` 退出码判定**守护进程可达**，替代原"只看 CLI 在不在"。
- 给 `test_stage5_integration.py`、`test_stage6_integration.py`、
  `integration/test_default_strategy_e2e.py` 打 `pytest.mark.integration`，
  并把 stage5/6 守卫升级为守护进程可达性检查。

## 验证

| 命令 | 结果 |
|------|------|
| `pytest poirot/backend/tests/ -q` | **2720 passed, 4 skipped, 1 deselected**（修复前 6 failed） |
| `pytest poirot/backend/tests/ -q -m integration` | **3 skipped, 2722 deselected**（无 Docker 守护进程 → 跳过而非报错） |
| 旧污染顺序 e2e→unit/config 单进程 | **29 passed, 1 skipped**（不靠挡板即通过） |

## 兼容性与风险

- **默认"全量"语义变化**：现在默认排除集成层。完整门禁为叠加运行：
  `pytest` 之后再 `pytest -m integration`。已同步 `USAGE.md`、`resource/USAGE.zh-CN.md`、
  `resource/USAGE.ja.md`。
- **未改生产代码**：`app/cli/main.py` 的模块级 `load_dotenv` 属冗余导入副作用
  （`main()` 内已有 `override=True` 的加载），但隔离层已通用地兜住它，且对
  "未来任何新增的模块级 `load_dotenv`"同样有效，故本轮不动生产代码，避免扩大
  变更面。
- 隔离偏严：某用例若依赖跨测试的环境变更会立即暴露（期望行为）。

## 遗留

- 建议为隔离层本身补一组"元测试"（污染一个 `os.environ` 键、再验证后续不可见），
  本轮未做。
- `local_container_backend.py` 缺显式 `docker pull` 的真实风险仍在（见变更记录 0005）。
