日期：2026-09-28
类型：变更
关联：[建立测试环境隔离层并分层集成测试](0008-2026-09-28-变更-建立测试环境隔离层并分层集成测试.md) ·
[测试隔离质量评审](../reviews/0001-2026-09-28-评审-测试隔离质量.md)

## 背景

变更记录 0008 留下三项未收尾的遗留：生产代码 `app/cli/main.py` 的模块级
`load_dotenv` 未清除（当时由隔离层通用兜住）、`local_container_backend.py`
缺显式 `docker pull` 的真实风险仍在、隔离层本身没有元测试锁住。本轮逐项收口。

## 核心变更

### 1. 删除 `app/cli/main.py` 的模块级 `load_dotenv`

`main.py` 顶部曾无条件执行 `load_dotenv(_PROJECT_ROOT / ".env")`。这是纯粹的
**导入副作用**：任何 `import` 该模块的调用方（典型是测试，例如
`test_recursion_limit.py` 从它导入 `_build_stream_config`）都会被灌入整个 `.env`——
0008 实测 `OPENAI_MODEL` 由 `None` 变为 `gpt-5.6-sol`。而 `main()` 内**已有**
`load_dotenv(_PROJECT_ROOT / ".env", override=True)`，模块级那次拉取对程序行为
毫无贡献，只对外泄污染。故直接删除，并把原因写进 `_PROJECT_ROOT` 旁的注释。

已核对删除的安全性：TUI 由 `main()` 内部延迟导入（`from poirot.backend.app.tui
import PoirotTUI` 在 `run_chat` 内），CLI 与 `run` 子命令路径都先经 `main()`；
被外部导入的 `_build_stream_config` 只读 `run_context.config.runtime`，不读环境变量。

### 2. 容器创建前显式 `docker pull`

`LocalContainerBackend.create()` 此前依赖 `docker run` 的隐式拉取。风险：
沙箱镜像可达 10 GB+，首次启动会**静默**拉取整个镜像——无进度、无独立超时边界，
且拉取失败的错误会和"容器启动失败"混在一起，难以定位（此风险在变更记录 0005
已记录未修）。

新增 `_image_present()`（以 `docker image inspect` 的退出码判定本地是否已有镜像，
兼容 docker/podman）与 `_ensure_image()`（缺失时 `docker pull`，失败抛
`RuntimeError("Failed to pull sandbox image ...: <stderr>")`）。`create()` 在
`discover()` 早返回之后、端口重试循环**之前**调用一次——放在循环内会让每次
重试都重复探测。

### 3. 隔离层元测试

新增 `poirot/backend/tests/test_conftest_isolation.py`。此前的隔离层没有自身测试：
一旦有人改动 `conftest.py` 把它改坏，全量套件**依然全绿**（隔离失效的表现是
"不再拦住污染"，而不是报错），缺陷会静默潜伏到下一次验收。

该文件用成对用例把隔离行为钉死——每对中的第一个用例**故意**直接改全局状态且
不清理，紧随其后的用例断言看见的是干净状态：

| 污染方 | 断言方 | 锁住的能力 |
|--------|--------|-----------|
| 新增 `POIROT_META_TEST_LEAK` 环境变量 | 该键不可见 | 新增键的清除 |
| 篡改既有的 `PATH` | `PATH` 已还原 | **已存在变量的还原**（非仅清除） |
| 注入无 `__file__`/`__path__` 的假模块 | 该模块已移出 `sys.modules` | 占位模块清理 |

用例依赖 pytest 在文件内按定义顺序执行。这是刻意的：宁可依赖一个稳定的
pytest 行为，也要让"隔离层失效"变成一条红色用例，而非一次线上困惑。

## 验证

| 命令 | 结果 |
|------|------|
| `pytest poirot/backend/tests/test_conftest_isolation.py -q` | **6 passed** |
| `pytest poirot/backend/tests/v1/unit/sandbox/test_local_container_backend.py -q` | **62 passed**（含新增 `TestEnsureImage` 3 例） |
| `pytest poirot/backend/tests/ -q` | **2729 passed, 2 skipped, 7 deselected，零失败** |

删 `load_dotenv` 未引起任何回归；容器后端的既有 mock 序列已按新增的
`image inspect` 调用同步更新（`call_args_list` 索引 1 → 2，重试与冲突路径补齐
条目）。

## 兼容性与风险

- 删除模块级 `load_dotenv` 属行为收敛：仅影响"导入 `app.cli.main` 但不调用
  `main()`"的场景——那种场景本就不该拿到 `.env`。
- `_ensure_image` 不改变镜像来源与版本，只是把"隐式拉取"改为"显式探测 + 拉取"。
  多一次 `docker image inspect`（毫秒级）换取失败时的可诊断性。
- 元测试的用例内依赖定义顺序；若未来引入随机顺序执行（`pytest-randomly`）需要
  改造该文件（例如改为显式构造脏状态）。

## 遗留

- 集成层（`-m integration`）在无 Docker 守护进程的机器上仍需等待探测超时才跳过，
  收尾验证时不跑该层；完整门禁为 `pytest` 之后再叠加 `pytest -m integration`。
