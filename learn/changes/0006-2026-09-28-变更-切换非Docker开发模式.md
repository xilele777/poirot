# 切换非 Docker 开发模式

日期：2026-09-28

## 背景

沙箱镜像约 13.1 GB，本机还残留了一份废弃的 `all-in-one-sandbox:latest`
（修复镜像名前的旧默认值），合计约 26 GB。Docker 仅为沙箱的其中一种后端，
默认即禁用。为轻量开发，将环境切换到非 Docker 模式。

## 配置变更（写入本地 `.env`，不提交）

| 项 | 值 | 说明 |
|----|----|------|
| `POIROT_SANDBOX_USE` | `LocalSandboxProvider` | 沙箱跑在宿主进程，无容器隔离 |
| `POIROT_SANDBOX_EXECUTOR` | `local` | 与 Windows/Docker daemon 同 OS |
| `POIROT_SANDBOX_ALLOW_HOST_BASH` | `true` | 经确认放开；危险命令仍被黑名单拦截 |
| `POIROT_MCP_ENABLED` | `false` | MCP 依赖 npx/Node，默认关闭 |
| `OPENAI_BASE_URL` | 中转站地址 | 用户提供 |
| `OPENAI_MODEL` | `gpt-5.6-sol` | 中转站实际可用型号 |
| 其余 `*_API_KEY=` 空行 | 注释掉 | 见下方"发现的缺陷" |

`.env` 已被 `.gitignore` 忽略，本记录不包含任何密钥。

## 过程中发现并绕过的缺陷

**只配置 OpenAI 时启动即失败。** `provider_config.py` 的 `MODEL_ROUTES` 为
`researcher: [openai, qwen, ...]`、`reporter: [qwen, deepseek]`、
`reflection: [deepseek]`。当只有 `OPENAI_API_KEY` 时，`discover_available_providers`
返回 `[openai, ollama, fake]`，`route_chain_for("reporter")` 与 `("reflection")`
会抛 `ProviderConfigError: no available provider`。而 `bootstrap.py:461` 在启动
路径上直接 `build_model("reporter")`，并非延迟加载——因此单 OpenAI 配置会
启动即崩。

绕过方式：`poirot --provider openai` 走 `bootstrap.py:452` 的单 provider 分支，
用同一模型充当 researcher 与 reporter，不经路由链。此为 CLI 参数，未改代码。

本缺陷未修复，仅记录。若日后要以"只配一个非 DeepSeek provider"作为正式
支持路径，需调整 `MODEL_ROUTES` 或 `route_chain_for` 的空链兜底。

## 另一发现：空 `KEY=` 会覆盖 shell 环境变量

`cli/main.py:39` 的 `load_dotenv(..., override=True)` 会以 `.env` 中的空值
覆盖 shell 里已导出的环境变量。因此 `.env.example` 里的空 `*_API_KEY=`
在 `override=True` 下会清掉 shell 注入的 key。本地 `.env` 已将这些空行注释，
避免覆盖。此行为与"模板可直接复制"的预期不符，是否调整模板注释说明，留待后续。

## 验证

- LLM：`gpt-5.6-sol` 经中转站可正常对话。
- 沙箱：`LocalSandboxProvider` 实例化、`acquire`、`execute_command("echo ok")`
  均正常，全程未接触 Docker；`rm -rf /`、`eval` 等危险命令被
  `LocalSecurityGuard` 黑名单拦截。
- 运行时：`bootstrap_runtime(provider="openai")` 成功，`AppRuntime` 构建完成。
- 完整测试套件不受本次配置影响（沙箱相关测试用 mock）。

## 后续

- 废弃镜像 `all-in-one-sandbox:latest`（13.1 GB）可删除，无任何引用。
- 上述两个缺陷（单 provider 路由空链、空 KEY 覆盖）可在需要时修复。
