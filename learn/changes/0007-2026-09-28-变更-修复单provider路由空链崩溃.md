# 修复单 provider 路由空链崩溃

日期：2026-09-28

## 背景

切换到非 Docker 模式时发现：只配置一个非 DeepSeek/Qwen 的 provider（如
OpenAI）时，项目启动即崩溃。

## 缺陷一：角色路由链为空时抛错

`provider_config.py` 的 `MODEL_ROUTES` 为：

```python
"researcher": ["openai", "qwen", "anthropic", "gemini", "deepseek"],
"reporter":   ["qwen", "deepseek"],
"reflection": ["deepseek"],
```

`route_chain_for` 按角色路由筛可用 provider。当只有 `OPENAI_API_KEY` 时，
`reporter` 与 `reflection` 的角色链与可用 provider 无交集 → 链空 → 抛
`ProviderConfigError`。而 `bootstrap.py` 在启动路径上直接
`build_model("reporter")`，并非延迟加载，因此单 provider 启动即崩。

### 修复

`route_chain_for` 在链空时回退到全部可用 provider（排除 `no_key_required`
的 fake/ollama），而非抛错。完全无 provider 时才抛错（语义保留）。

- 回退排除 fake/ollama：它们默认 `enabled` 且无需 key，会被
  `discover_available_providers` 收进来，但它们是测试/本地 provider，
  不是真实降级目标。

## 缺陷二：`.env` 引入的测试环境污染

修复一后全量测试暴露一个新问题：`test_provider_config.py` 断言
`select_provider_config("openai").model == "gpt-4.1-mini"`，但本地 `.env`
写了 `OPENAI_MODEL=gpt-5.6-sol`，且 `integration/test_default_strategy_e2e.py`
在模块导入时 `load_dotenv()`，把 `.env` 的值灌进 `os.environ`，污染后续
用例（按目录顺序 unit/config 在 integration 之后跑时成立）。

### 修复

`test_provider_config.py` 加 autouse fixture，清除 `*_MODEL` 环境变量。
与仓库既有测试隔离风格一致（如 `test_claude_credential.py` 的凭据隔离）。

## 验证

- `test_model_router.py`：16 passed（含 3 个新增用例）。
- 污染链 `integration/test_default_strategy_e2e.py` +
  `unit/config/test_provider_config.py` 同跑：20 passed / 1 skipped。
- 完整套件：**2726 passed, 3 skipped, 0 failed**（较上轮 2723 多 3 个新增测试）。

## 说明

本次修复使得"只配一个非 DeepSeek 的 provider"成为可用路径。此前需
`--provider` 单 provider 模式绕过（见 0006 记录），现在路由模式也能正常工作；
`--provider` 仍作为调试/强制单 provider 的入口保留。
