# 修复失败证据污染与报告导出

日期：2026-10-02。

## 现象与复现

用户按上手指南执行普通问答、整理 Markdown 短文、`/report` 后，报告保存的却是搜索错误 JSON。完整运行记录还显示搜索失败时出现成功勾号，第二轮读取会话时出现 Observation/AgentError 未注册反序列化类型警告。

核对本地运行日志，单次搜索同时出现 `tool.failure_streak` 和 `tool.finished status=ok`；已保存报告也确实只含错误结果。此前的 Responses 回答重复显示在这份记录中未再出现。

## 原因

1. 内置搜索把失败表示为错误 JSON，但默认 ToolMessage 状态仍是 success。EvidenceMiddleware 未检查业务错误，直接创建 Observation/Source。
2. ToolCallMiddleware 对 Command 的字符串表示做分类，既可能遗漏明确错误，也可能将成功搜索文章中出现的 `403` 等词误判为失败；失败账本未同步到 ToolMessage 状态。日志状态检查只识别字典形式的错误账本，忽略实际 AgentError 对象。CLI/TUI 则固定绘制成功标记。
3. 手动 `/report` 沿用研究报告兜底顺序，优先旧 `final_report` 或累积 observations，所以最新整理好的 AI 回答被旧搜索错误遮住。
4. InMemorySaver 默认 serializer 未显式注册应用自定义状态类型，当前依赖允许读取但告警；更严格的默认策略会影响兼容性。

## 改动

- 新增共享工具错误解析，识别 ToolMessage 显式 error 状态及顶层 JSON 错误结构；不按成功 JSON 中的文章关键词判断成败。
- EvidenceMiddleware 的同步/异步路径均拒绝把明确失败结果存成观察或来源；保留错误消息供模型判断。
- 工具账本读取 Command 中真实 ToolMessage 并同步 error 状态；日志支持 AgentError 记录。流式事件携带 `tool_status`，CLI、TUI 对话和执行面板按实际状态显示 `✗`/`✓`。
- 手动 `/report` 优先导出最新完整 AI 回答，跳过工具调用前言；仅修改导出副本，不改会话检查点。缺少完整回答时保留已有报告/证据兜底。报告仍不额外调用模型，也仍默认覆盖同会话的 `report.md`。
- 为检查点显式注册 9 种研究状态记录及专家 ArtifactRef；保留 LangGraph 内置安全类型，不开放任意模块、不使用 pickle 兜底、不通过关闭警告掩盖问题。
- 同步修正上手指南和当前限制中的手动报告语义。以前文档记录的是当时实现，旧变更记录保持不改。

## 验证

- 新增回归先复现错误证据入库、成功文章误判、旧证据/旧报告覆盖最新回答，以及自定义类型警告。
- 相关失败证据、报告、检查点、工具账本、日志和流式测试第一轮 **59 passed**。
- 新增离线完整链路：模拟 DuckDuckGo 失败 → 实际应用 Agent 图 → 连续两轮对话 → 检查点读取 → CLI 失败标记 → 报告落盘，确认只保存最新短文且无类型注册警告；另覆盖 TUI 状态与两种流式模式。该组 **31 passed**。
- 最终默认全量：**2785 passed / 4 skipped / 1 deselected，74.03 秒**。两组相关测试有重叠，不将通过数相加。
- 本轮没有调用真实模型或搜索服务；真实 DuckDuckGo 的可达性、空结果原因和研究质量仍需另行验收。

## 使用与下一步

退出已运行的 CLI 后重新启动，才能加载代码和检查点 serializer。进程内会话不会跨重启保留，需重新提供问题或短文，再执行 `/report`。已有错误报告不会自动恢复，也未在本次修复中覆盖。

基础概念问答可在问题中说明“不需要联网”；这属于模型指令而非硬性网络开关。需要最新资料时，再独立验证搜索结果及来源。下一步继续按[上手指南](../../docs/quick-start.md)验收报告内容与文件输出。
