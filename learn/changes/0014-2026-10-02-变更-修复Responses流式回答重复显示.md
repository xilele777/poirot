# 修复 Responses 流式回答重复显示

日期：2026-10-02。

## 现象与原因

用户在传统 CLI 中完成一次普通问答后，同一段回答连续显示两遍。运行日志显示一次模型请求和一次正常响应，基本连接已成功；专家凭证缺失和 MCP 数量为零不是该重复的原因。

通过当前配置接口与真实应用 Agent 图复现，最终状态只有一条 AI 回答，但流式服务输出了两份。Responses 流开始时发出带 provider response ID 的空片段，文本片段使用另一个 LangChain run ID，最终完整消息又使用 provider ID。原先仅按已有正文的消息 ID 去重，不能关联这两个身份，因此把最终状态全文再次当作新答案输出。

## 改动

- 在[流式服务](../../poirot/backend/app/services/stream_service.py)中按模型调用范围关联 provider ID 和 delta ID，供片段缓冲与完整状态共用；不修改原始消息，也不按文字相同跨调用删内容。
- 完整 `AIMessage` 作为快照处理，避免当成增量再次追加；最终状态替换尚未判定的 JSON 缓冲，避免结束时重复 flush。
- 空片段和仅含 reasoning 的片段不再被当作正文已经输出，保留完整消息的回答兜底。
- 增加[行为回归](../../poirot/backend/tests/v1/unit/services/test_stream_service.py)：覆盖 messages/values 两种完整消息回放、普通文本与短 JSON、空/思考片段、相同文字的独立调用、交错调用隔离和调用结束边界。
- 增加离线 Responses SSE → 真实 OpenAI SDK → LangGraph → 流式服务 → CLI 渲染的集成回归，用模拟 HTTP transport 阻止真实网络请求。

## 验证

- 修复前新增用例实测出现 7 个失败，包含重复输出与 reasoning 后完整回答丢失；原有用例通过。
- 修复后相关服务、CLI、TUI、普通对话和最小 Agent 集成测试合计 **69 passed**。
- 使用当前配置的 OpenAI 兼容接口和真实应用 Agent 图复核短回复：最终状态 1 条 AIMessage，显示内容与最终状态一致，诊断标记仅出现一次。
- 本轮真实诊断共 3 次短问答调用：最小图定位、实际应用图复现及修复后复核；不把这些短问答视为完整研究质量验收。未把真实凭证、接口地址或对话正文写入仓库。

## 使用方式与范围

源码 editable 安装无需重装，退出已启动的 CLI 后重新启动即可加载修复。CLI/TUI 共用本次修复的流式服务；本轮未对全屏 TUI 做真实交互验收。

外部专家警告表示对应可选 CLI/凭证尚未可用，普通模型问答仍可进行。首次使用可在 `.env` 中关闭 `POIROT_MULTIAGENT_ENABLED`，无需为了普通聊天安装所有专家。模型回复自身不掌握型号时，应看界面请求模型名或运行日志；横幅 `v1.0.0` 为现存硬编码展示，仍见[限制清单](../../docs/known-limitations.md)。
