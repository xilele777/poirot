# 统一可选依赖占位注入并评估 CI 镜像方案

日期：2026-09-28

## 一、统一 `agent_sandbox` 占位注入（计划事项五）

### 起因

原计划将"占位注入统一为 fixture 方案"列为工程优化。排查中发现它并非风格
问题，而是一个**真实缺陷**。

### 缺陷：占位模块能骗过 `pytest.importorskip`

`test_docker_runtime.py`、`test_docker_sandbox_provider.py` 在模块级注入
`agent_sandbox` 占位（`types.ModuleType` + `Sandbox = MagicMock`），
使自身在未安装可选依赖时仍可导入。stage5/6 集成测试用
`pytest.importorskip("agent_sandbox")` 判断依赖是否可用，但该函数只检查
导入是否抛 `ImportError` —— 占位模块已在 `sys.modules` 中，导入必然成功。

后果：同一进程内先导入上述单测文件后，集成测试不再跳过，而是带着假 SDK
运行，在运行时崩溃，把"缺少可选依赖"变成**误报失败**。

已实证复现（临时移走 site-packages 中的 `agent_sandbox`）：

```
旧写法：test_a_unit_like.py + test_b_integration_like.py
      → 1 failed, 1 passed      # 集成测试未被跳过，误报失败
新写法：test_a_unit_like.py + test_b_fixed_like.py
      → 1 passed, 1 skipped     # 正确跳过
```

### 修复

- 新增 `tests/v1/fixtures/sdk_stubs.py`，提供 `install_stub_if_missing()`
  与 `has_real_agent_sandbox()`。
- 两个单测文件改为调用 `install_stub_if_missing()`，不再各自展开注入代码。
- stage5/6 改用 `has_real_agent_sandbox()` 判定并显式 skip。

`has_real_agent_sandbox()` 的判据是模块的 `__file__` / `__path__`，而非
自定义标记。最初版本用标记实现，但实测发现它只识别"自己注入的占位"：
若某处仍按旧写法注入无标记占位，判定会误认为依赖可用。改为验证模块来源后，
无论占位由谁注入都能识别，不依赖注入方配合。

### 验证

- 未安装环境下运行 `unit/sandbox/`：**613 passed, 2 skipped**，无误报失败。
- 已安装环境下运行 `unit/sandbox/`：619 passed。
- 完整套件：**2723 passed, 3 skipped**，与改动前一致，无回归。

## 二、CI 沙箱镜像方案（计划事项四）

### 结论：不做，记为待触发

原计划为"镜像约 13 GB，CI 中不宜每次拉取，可考虑构建缓存或更小的替代镜像"。
排查后发现该事项**前提不成立**：

- 仓库没有任何 CI：无 `.github/` 目录，无 workflow 文件。
- 项目未定义任何 pytest 配置（无 `testpaths` 等），测试依赖手工运行。
- 若在 GitHub Actions 上跑，13.1 GB 镜像会超出 runner 的磁盘配额，
  需要先调研替代镜像——在没有 CI 的情况下属空转。

### 改为记录的真实风险

`local_container_backend.py` 的 `docker run` 调用（约 228 行）**没有显式
`docker pull`**。镜像缺失时，Docker 会在 `docker run` 时静默拉取 13.1 GB，
表现为长时间无输出而非明确报错。这是当前实际存在的可用性风险，与 CI 无关。

### 触发条件

待真的引入 CI 时，或本地首次运行沙箱集成测试耗时异常时，再处理本项。
届时需要：

1. 决定 CI 是否覆盖需 Docker 的集成测试（stage5/6 已可正确跳过）。
2. 若覆盖，调研更小的替代镜像，或改用预构建层 + 缓存。
3. 为该镜像缺失场景补一条明确的提前检查与提示。

### 顺带发现：`test_stage6_bootstrap.py` 的注入是死代码

该文件为 `langchain_core` 准备了占位注入分支（17-19 行）。但 `langchain_core`
是 `pyproject.toml` 的必装依赖，该分支永不触发。本次未改动——它不产生
误报失败（判定用的是 `HAS_LANGCHAIN` 标志，非 `importorskip`），
移除属可选清理，避免扩大本次改动范围。
