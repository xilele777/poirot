# 能力与限制

本页描述当前应用入口的实际能力；模块内存在某个类或方法，不代表已经接入用户流程。

| 能力 | 实际范围 |
|---|---|
| Agent 与上下文 | ReAct 图、工具路由、middleware、上下文压缩与外置已有实现 |
| 记忆 | Markdown 真源、BM25、衰减、可选后台巩固；默认空格分词，不含向量/图数据库实现 |
| Skill | 加载、选择、注入、版本存储；启用后可手动 evolve/capture |
| Skill 自动化 | run_cycle 与 GitRatchet 为实验组件，尚未接入后台调度 |
| 专家委派 | 支持配置外部 CLI/子 Agent；环境、凭证、工具权限需要独立验证 |
| 专家进化 | 应用没有真实 mutation caller/task evaluator；L2/L3 开关在启动前被拒绝，不启动空转线程 |
| 恢复 | InMemorySaver 保存进程内状态；重启后不能靠 thread_id 恢复完整会话 |

## 文件和命令边界

LocalSandboxProvider 在宿主执行进程，不是隔离容器。Docker 的文件路径校验拒绝 traversal 和不合法组件，命令校验覆盖直接绝对路径重定向（含引号），但不是完整 shell 语义分析：相对路径、变量展开、tee、脚本内部写入不受该正则全面约束。不要把它描述成“所有命令写入均强制持久化”。

产物导出要求显式映射、合法虚拟路径及成功复制；Docker/Local 翻译器解析符号链接并验证映射归属，目标在解析后验证输出目录归属。翻译失败、文件缺失或复制失败不返回成功下载地址。自定义 translator 必须遵守同样的宿主路径契约。

这些检查不构成对恶意宿主进程并发替换文件或符号链接的防护，也不等同对本地不可信代码的完整隔离。API 凭证、网络和容器运行权限应按实际部署配置。

## 记忆一致性

MarkdownFileStore 使用稳定的 `traces.lock` sidecar 排他锁，写入前在锁内重读最新数据，并以同目录临时文件、flush/fsync、原子替换提交。实例读取会刷新外部变化；检索索引同步新增、变更、删除和 forgotten 状态。检索强化使用条件更新，避免将并发修改/删除的旧记录写回。

单次 store 操作协调独立实例/进程，批量更新一次提交。它不是横跨多次 manager 调用的数据库事务。同一 trace 的显式 `update` 保持完整替换语义；需要避免同记录旧值覆盖的调用方应使用 `compare_and_update`。当前每次提交仍全量序列化文件，大规模记忆需单独做性能评估。网络文件系统的锁和原子替换语义未验收。

## 进化与评估

手动 Skill 进化的当前门控检查 Skill 文本规则，不等同候选与基线在固定真实任务上的效果对照。版本创建或记录失败会向调用方抛错，不再伪装为成功进化；创建版本和写评估记录仍是两个存储操作，记录失败时版本可能已创建，应查阅版本历史再重试。

自动进化要完成独立阶段：固定评估任务、模型调用器、成本预算、候选隔离、提升/回滚准则以及可审计发布流程。当前默认不自动修改 Skill。
